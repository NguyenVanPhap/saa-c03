## Câu 401 — App on-prem vừa mất data vì cúp điện, cần HA, không SPOF, scale theo demand

- A. **ASG nhiều AZ + RDS Multi-AZ**
- B. ASG một AZ + DB trên EC2 + Auto Recovery
- C. ASG nhiều AZ + RDS + **một** read replica, promote khi primary chết
- D. ASG nhiều AZ + MySQL tự dựng EC2 + **EBS Multi-Attach**

**Đáp án: A.** Power outage = mất một máy/một AZ. Multi-AZ RDS replication **đồng bộ**, failover tự. ASG nhiều AZ scale và chống chết AZ.

B một AZ vẫn SPOF. C replica bất đồng bộ, promote tay, RPO không zero. Multi-Attach không biến hai MySQL thành cluster HA.

**Tầng 4+6.** Câu 69, 281.

## Câu 402 — Kinesis default, app consume **cách ngày** rồi ghi S3, S3 **thiếu data**

- A. **Tăng retention** Kinesis
- B. Dùng KPL
- C. Tăng số shard
- D. Bật S3 Versioning

**Đáp án: A.** Default retention **24 giờ**. Consume **mỗi 2 ngày** → record hết hạn trước khi đọc. Tăng retention (tới 365 ngày). Shard liên quan throughput/throttle, không giải “đọc muộn”. Versioning không tạo object chưa bao giờ tới.

**Tầng 5.**

## Câu 404 — S3 → Lambda xử lý document, sau campaign **nhiều file không được xử lý**

## Câu 406 — Public web 443; RDS chỉ web trên 3306 (chọn hai)

- A. NACL deny outbound 3306 ra internet
- B. SG DB allow **CIDR public subnet** 3306
- C. **SG web allow 443 từ 0.0.0.0/0**
- D. **SG DB allow 3306 từ SG web**

## Câu 419 — Org + SCP chặn Region khác; audit: EBS **không mã hóa**; mọi launch mới ở ap-southeast-2 phải encrypted, ít ảnh hưởng NV (chọn hai)

- A. **Bật EBS encryption by default** (+ default key)
- B. Permission boundary trên OU root (boundary không attach OU như SCP)
- C. **SCP deny CreateVolume khi ec2:Encrypted = false**
- D. Sửa IAM từng account
- E. Setting default encryption ở **management account** (không áp member như vậy)

**Đáp án: A và C.** Default encryption = UX gần như không đổi. SCP chặn ai cố tạo volume không mã hóa (kể cả root member). Câu 371.

## Câu 420 — RDS PostgreSQL, HA failover **< 40 giây**, offload đọc, rẻ

- A. Multi-AZ **instance** + 1 replica
- B. Multi-AZ **cluster** + 2 replica thêm
- C. Multi-AZ instance, đọc **secondary** (không đọc được)
- D. **Multi-AZ DB cluster**, đọc qua **reader endpoint**

**Đáp án: D.** Multi-AZ *cluster* (RDS) có writer + **2 readable standby**, failover thường ~1–few giây tới < 40s, reader endpoint offload — không trả thêm replica riêng. Instance Multi-AZ failover ~60–120s, standby mù.

**Tầng 6.**

## Tổng kết Phần 21

Kinesis default **24h** — consume cách ngày thì mất data (402). S3→Lambda burst → **SQS** (404). Aurora Serverless khi MySQL + tải thất thường (411). Compute SP khi có **cả EC2 lẫn Lambda** (417). RDS Multi-AZ **cluster** ≠ Multi-AZ instance (420).
